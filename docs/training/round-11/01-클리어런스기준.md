# 11차 — 발 높이를 지형 위에서 재기

10차는 험지에서 안 죽고 레벨 6까지 올라갔다. 거기서 800 iter 동안 멈췄고,
`feet_air_time` 은 7차부터 네 라운드째 0.011 이고, `mean_std` 는 0.77 → 1.01 로 벌어졌다.

원인은 보상 하나였다. `foot_clearance` 가 발 높이를 **세계좌표 상수** 위에서 쟀다.

```python
ground = _FOOT_RADIUS          # 0.036 m
lift = clamp((foot_z - ground) / 0.044, 0, 1)
```

평지에선 맞는 식이다. 9차 걸음이 이 항에서 나왔다.
험지 생성기는 서브지형 원점 z 가 0이 아니다 — 피라미드 계단은 최대 +1 m, 역계단은 −1 m.

256환경 · **행동 0 (가만히 서 있음)** 으로 실측 (`check_foot_clearance_reference.py`):

| 서브지형 원점 z | 환경 수 | 세계 z 기준 | 지형 상대 |
|---|---:|---:|---:|
| −0.05 m 아래 | 76 | 0.000 | 0.001 |
| +0.05 m 위 | 180 | **0.976** | 0.041 |
| 전체 | 256 | **0.686** | 0.029 |

발을 하나도 안 들었는데 0.686. 10차 학습 기록의 `foot_clearance` 1.14 가 거의 다 이 값이다.
계단 위(환경의 70%)에서는 항이 1.0에 붙어 **발을 들어도 더 받을 게 없고**,
역계단에서는 0에 붙어 **발을 들어도 받을 게 없다.**

9차 평지 걸음을 만든 유일한 신호가 험지에서 양쪽으로 다 죽었다.

## 이번 한 가지

`foot_clearance` 의 바닥 기준을 **그 발 아래 지형 높이**로 바꾼다. 다른 건 안 바꾼다.

```python
ground = _ground_height_under_feet(env, foot_pos, sensor_cfg) + _FOOT_RADIUS
```

지형 높이는 **이미 있는 `height_scanner`** 의 레이 히트 중 발 xy 에 가장 가까운 점에서 가져온다.
새 센서를 안 붙였으므로 관측 차원이 그대로고, 10차 체크포인트를 그대로 resume 할 수 있다.

- 평지에서는 `ground = 0.036` 이라 9차·10차 식과 **완전히 같다.** 순수한 버그 수정이다.
- 스캐너 격자가 0.1 m 라서 계단 모서리에서는 옆 단을 집을 수 있다. 오차는 단 높이 하나(5–23 cm)다.
  세계좌표 0을 쓰면 오차가 서브지형 원점 전체(최대 ±1 m)였다.
- 실측 잔차: 스캐너가 읽은 지형 z 와 환경 원점 z 의 평균 절대차 **0.009 m.**

`target_height` 0.08, 가중치 2.0, PD 80/3, 명령 0.5–1.5 m/s, 커리큘럼, `termination_penalty` −200 —
전부 10차와 같다.

resume: `2026-08-17_15-28-30/model_4150.pt` · 4096 환경 · 1500 iter.

## 게이트

10차 끝(iter 4186)과 비교. 지형 레벨은 resume 하면 0에서 다시 오른다.

| 보이면 | 뜻 |
|---|---|
| `foot_clearance` 가 0.1 밑으로 떨어져서 안 올라옴 | 항이 죽음. 발을 드는 게 아니라 10차가 지형 높이만 먹고 있었고 걸음 자체가 없었다는 뜻 |
| `foot_clearance` 1.0 근처 유지 + `mean_std` 하락 | 같은 크기를 이제 **발을 들어서** 받는 중. 이게 목표 |
| 지형 레벨이 6을 넘어감 | 정체 원인이 이 항이었음이 확인 |
| 레벨이 다시 6에서 멈춤 | 클리어런스는 원인이 아니었음. 다음은 스윙 길이(`feet_air_time` 기준 0.1초)나 명령·PD 쪽 |
| `feet_air_time` 0.011 그대로 | 발은 들지만 스윙이 0.1초를 못 넘음. 12차는 `target_height` 를 계단 높이 쪽으로 올리는 것 |
